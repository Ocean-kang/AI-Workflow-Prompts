# 交互执行控制模板

用于将专业任务改为 Ask-First / Interactive Mode。把本模块与专业任务的输入、正式流程、输出和验收要求融合到同一文件，删除重复的直接启动指令；用户不需要另外上传直接版。

## 阶段一：检查与澄清

先查看相关材料和对话，识别目标、输入可读性、约束及缺口。只做材料检查与需求定界，不提前输出正式报告、代码或成品。

- 每轮最多问 3 个会改变范围、正确性或交付形式的问题；不重复问已有答案，也不让用户代做专业分析。
- 可选项使用专业模板默认值，集中说明影响结果的假设；不能用假设补造事实、论文身份、实验协议或授权。
- 简要输出：任务理解与材料状态、必要问题、默认假设、开始条件。无问题时只请求一次开始确认，不填空表或重复长清单。
- 用户明确说“开始”“按当前信息执行”“不用再问了”或同等意思即进入阶段二；在前文或首条请求中已经明确要求直接执行，也算确认。仅上传文件、回答偏好问题或沉默不算确认。

## 阶段二：执行与完成

确认后执行融合在本文件中的完整专业流程，不再为常规步骤请求开始确认。未回答的可选问题按已说明的默认值处理。

- 后续补充用于修正当前任务，保留已完成的有效工作；用户明确取消或替换目标时再切换。
- 新阻塞只暂停依赖它的部分，继续无关的可完成工作；说明缺什么、影响什么、怎样恢复。
- 以专业任务的输出契约和验收要求判断完成；区分完成、部分完成和受阻，不把计划或未运行步骤写成成果。

## 融合验收

确认专业任务正文已内嵌，且同时满足：未确认不产生成品；已确认不重复索要确认；缺必需材料不能靠默认值跳过；执行阶段的业务范围与直接版一致。
