# Output Format Template

这是可裁剪的结果呈现模板，不负责控制执行阶段或覆盖专业任务流程。用户明确指定格式时优先使用该格式；否则按任务需要选择以下小节，避免与专业模板重复套用。空值写“未知”“未提供”或“不适用（原因）”，不要保留空表。

## 1. Result

先回答用户核心问题或提供交付物。文件必须附真实路径或下载链接；未生成文件时说明实际交付形式。

## 2. Context and Coverage

简述目标、用途、实际读取的材料与版本、采用的关键假设。仅列影响结果的信息，不重复复述全部输入。

## 3. Core Analysis

沿专业 workflow 的问题或步骤展开，解释依据与结论之间的关系。可以使用下表组织需要比较的发现；无需每个任务都填表。

| Finding | Evidence / Location | Interpretation | Scope / Confidence |
| --- | --- | --- | --- |
| 具体发现 | 文件章节、图表、代码位置或来源链接 | 事实 / 推断 / 评价 | 支持范围与不确定性 |

## 4. Validation and Limitations

| Check | Status | Result / Impact |
| --- | --- | --- |
| 与交付物相关的检查 | 通过 / 失败 / 未执行 / 不适用 | 实际结果，或未执行的原因与影响 |

说明缺失材料、未解决问题和结论边界。没有读到某项信息不等于该信息不存在；未执行验证不等于通过。

## 5. Next Steps

只在存在未完成事项或用户需要后续行动时列出：具体动作、目的、优先级，以及恢复工作所需的输入。全部完成时不为了填模板增加建议。
